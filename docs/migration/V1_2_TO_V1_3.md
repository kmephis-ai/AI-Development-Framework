# Миграция ADWF v1.2 → v1.3

Миграция выполняется только при отсутствии активного Writer, незавершённого durable run и занятого workspace. Она не переносит старые зелёные статусы как доказательство: Product Health, acceptance и runtime evidence становятся `NOT_VERIFIED` до новой проверки.

## Безопасный порядок

1. Остановите новые задачи и завершите либо передайте активную работу.
2. Выполните предварительный просмотр:

<!-- adwf-doc: skip(reason=contextual-example) -->
   ```bash
   python3 .adwf/migrate_v1_2_to_v1_3.py --root .
   ```

3. Примените миграцию:

<!-- adwf-doc: skip(reason=contextual-example) -->
   ```bash
   python3 .adwf/migrate_v1_2_to_v1_3.py --root . --apply
   ```

4. Укажите разрешённые логины владельцев в `github.trust.trusted_reviewer_logins`. Пока список пуст, trusted controller честно блокирует merge.
5. Пересоберите производные артефакты и проверьте пакет:

<!-- adwf-doc: skip(reason=contextual-example) -->
   ```bash
   python3 .adwf/scripts/compile_policy.py --write
   python3 .adwf/scripts/docs_freshness.py --write
   python3 .adwf/scripts/generate_manifest.py
   python3 .adwf/scripts/validate_framework.py
   python3 .adwf/adwf.py doctor --json
   ```

Полный `doctor` до подключения repository/runtime закономерно оставляет Control Plane и Product в `NOT_VERIFIED`.

## Откат

Команда применения печатает путь к `manifest.json`. Для восстановления исходных config/state/policy используйте:

<!-- adwf-doc: skip(reason=contextual-example) -->
```bash
python3 .adwf/migrate_v1_2_to_v1_3.py --root . --rollback .adwf/migrations/<каталог>/manifest.json --apply
```

Backup проверяется по SHA-256. Миграция не повышает автономность: максимум после перехода — `A1`, а неизвестный/платный provider и любые ненулевые расходы остаются заблокированы.
