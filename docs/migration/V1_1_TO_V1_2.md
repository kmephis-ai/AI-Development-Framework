# Миграция ADWF v1.1 → v1.2

## Что меняется

- schema version 2 → 3;
- active autonomy принудительно не выше A1;
- max Writer 2 → 1;
- Node 24 и Python 3.12.13 фиксируются;
- строковые project commands отключаются до перевода в arrays;
- Health/evidence, которые нельзя перепроверить, становятся `NOT_VERIFIED`;
- self-hosted CI и monetary budget 0 становятся default;
- старые девять GitHub workflows заменяются четырьмя trust-separated workflows.
- live snapshot переносится в `.adwf-runtime`, а package template остаётся checksummed;
- строковые/пустые обязательные gates блокируют bootstrap до явной настройки;
- каждый active lease получает isolated workspace lifecycle.

## Безопасный порядок

1. Убедиться, что active Writer отсутствует. Иначе migration блокируется.
2. Выполнить dry-run: `python3 .adwf/migrate_v1_1_to_v1_2.py --root .`.
3. Прочитать предупреждения `STRING_COMMAND_DISABLED` и заранее подготовить arrays; для продукта указать unit/PR/main и, если он имеет runtime, smoke/Golden Paths.
4. Применить: `python3 .adwf/migrate_v1_1_to_v1_2.py --root . --apply`.
5. Сохранить выведенный путь `manifest.json`.
6. Выполнить manifest/structure/self-tests, затем repository reconciliation и Baseline/Reality certification.
7. Не повышать autonomy до прохождения первого полного R0/R1 lifecycle.

Тот же скрипт распознаёт `v1.2.0` и применяет узкий idempotent patch до `v1.2.1`: добавляет только новые schema fields (`runtime_product`, `golden_paths`, Security, `work_items`, active/workspace lease data и Project projection evidence), создаёт отдельный backup manifest и не сбрасывает уже подтверждённые данные.

## Rollback

<!-- adwf-doc: skip(reason=contextual-example) -->
```bash
python3 .adwf/migrate_v1_1_to_v1_2.py --root . --rollback .adwf/migrations/<id>-v1.1-to-v1.2/manifest.json
python3 .adwf/migrate_v1_1_to_v1_2.py --root . --rollback .adwf/migrations/<id>-v1.1-to-v1.2/manifest.json --apply
```

Первый вызов dry-run. Apply проверяет hashes backup, создаёт отдельный pre-rollback backup текущих файлов и только затем восстанавливает v1.1 config/state. После rollback требуется v1.1 doctor/self-test; framework code/workflows откатываются тем же governance PR/revert, а не скриптом состояния.
