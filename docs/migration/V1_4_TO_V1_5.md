# Миграция ADWF v1.4 → v1.5

## Что меняется

- schema/config переходят на v1.5;
- default active autonomy становится A2 с fail-closed policy; promotion/merge по-прежнему ограничены owner gates;
- добавляются Executive settings, Preview, Project Packs, Runtime Supervisor, Release Automation и Secrets policy;
- создаётся Work Memory model;
- сохраняется публичный `$0` default.

## Транзакционная миграция

Migration journal использует состояния `PREPARED → COMMITTED`. Перед заменой критических файлов создаётся backup. Fault injection tests проверяют rollback. Повторный запуск не должен считать частичную запись завершённой миграцией.

## Что миграция НЕ делает

Она не:

- меняет private repository на public;
- выбирает LICENSE;
- создаёт AI/API key;
- публикует release;
- меняет production data/schema;
- утверждает живой ruleset без provider readback.

## Инженерный запуск

<!-- adwf-doc: skip(reason=stateful-migration-command) -->
```bash
python .adwf/migrate_v1_4_to_v1_5.py --root .
```

Перед использованием на реальном project repository рекомендуется backup и clean working tree.
