# ADWF v1.6 — быстрый старт владельца

## Ваша роль

Вы не обязаны разбираться в ветках, SHA, workflows и JSON. В нормальном режиме ваша работа состоит из двух действий:

1. сказать, **какой результат нужен**;
2. посмотреть готовый результат и нажать **«ПРОДОЛЖИТЬ»**, если система говорит, что следующий шаг безопасен.

## Шаг 1. Откройте ADWF

Windows: двойной щелчок `START_ADWF.bat`.

Linux/macOS: `START_ADWF.sh`.

Portal работает только на локальном loopback-адресе и не должен становиться публичным web server.

## Шаг 2. Опишите задачу

Пример: «Сделай страницу регистрации с именем, email и паролем. Она должна хорошо выглядеть на телефоне».

ADWF создаёт Product Brief и Work Memory. Состояние работы не должно зависеть от того, открыт ли исходный чат завтра.

## Шаг 3. Подключение GitHub

Для нового проекта канонический профиль — `FREE_PUBLIC_GITHUB`. Владелец отдельно подтверждает публикацию и LICENSE. ADWF готовит/проверяет governance rules и показывает `VERIFIED` только после API readback.

## Шаг 4. Следите за результатом, а не за логами

Executive Portal показывает:

- работает ли продукт;
- что изменилось;
- визуальный preview;
- дорожную карту;
- проблему, если автоматическое продолжение небезопасно;
- одну рекомендуемую кнопку.

Технические SHA/evidence доступны только в раскрываемом разделе.

## Шаг 5. Preview

Для UI-изменения ADWF должен сформировать desktop/mobile preview. Пока реальный Playwright не запускался для вашего exact commit, Portal обязан показывать `NOT_VERIFIED`, а не картинку-заглушку как доказательство.

## Шаг 6. «ПРОДОЛЖИТЬ»

Эта кнопка не отключает проверки. Она подтверждает рекомендованное безопасное следующее действие. Если требуется owner authority для merge/release, решение должно быть связано с authenticated provider identity и exact SHA.

## Что делать при ошибке

Не лечите GitHub вручную первым делом. Посмотрите человеческое объяснение в Portal. Если ADWF может безопасно Recovery — он сформирует следующий шаг. Если не может — попросит конкретное решение владельца.

## Инженерная самопроверка (не обязательна владельцу)

<!-- adwf-doc: run -->
```bash
python .adwf/scripts/validate_ci.py
python .adwf/scripts/validate_pipeline_ir.py
python .adwf/adwf.py doctor --scope package_integrity
```

Если `Control Plane` или `Product Health` = `NOT_VERIFIED` до подключения реального repository/deployment — это корректно.

## Что важно именно в v1.6

- новая задача во время active run помещается в очередь и не подменяет текущий Brief;
- `ПРОДОЛЖИТЬ` после GitHub-authenticated acceptance записывает durable result и инициирует следующий trusted cycle;
- изменение самой защиты framework требует отдельного governance approval;
- Project Pack применяется через governance PR, а не скрытой правкой trusted config;
- public Runtime Ledger не является хранилищем текста вашего диалога;
- если AI adapter не подключён, система честно покажет `WAITING_AGENT`.
